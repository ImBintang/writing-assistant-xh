# AI 写文助手

> 本地运行的轻量级 AI 辅助长篇小说写作工具

**AI 写文助手** 是一个专为长篇小说作者设计的本地化写作工具。它将章节拆解、知识提取、知识库管理、知识图谱可视化和 AI 辅助撰写整合为一体，帮助作者高效管理复杂的架空世界观、人物关系和剧情线索。

---

## 核心功能

| 模块 | 说明 |
|------|------|
| **📑 章节管理** | 上传 `.txt` 小说文件，自动按正则规则拆分为章节，检测拆分异常 |
| **🧠 知识提取** | AI 自动从章节中提取人物、功法、地图、世界观、武器、丹药、情节七类知识 |
| **📚 知识库管理** | 浏览、搜索、编辑知识条目，支持版本历史、软删除与回收站 |
| **🕸️ 知识图谱** | Cytoscape.js 可视化展示知识节点间的关系网络 |
| **✍️ 写文窗口** | TipTap 富文本编辑器，支持大纲/正文双模式，AI 生成/续写/润色/扩写/缩写/改写/伏笔检查 |
| **📝 设定构思** | 独立隔离的设定编辑空间，支持从知识库引用，可迁移到知识库 |
| **💬 头脑风暴** | AI 对话式头脑风暴，支持多轮讨论和结论提取 |
| **⚙️ 系统配置** | 多模型配置（Claude / OpenAI / Ollama），功能模型映射，上下文预算管理 |

---

## 技术栈概览

- **前端**：React 19 + Vite + TypeScript + Tailwind CSS + Zustand
- **编辑器**：TipTap（富文本）
- **图谱**：Cytoscape.js（关系可视化）
- **后端**：Node.js + Express + TypeScript
- **AI**：Claude Agent SDK（支持 Claude / OpenAI / Ollama 多源）
- **存储**：SQLite（搜索索引）+ JSON 文件（版本管理）
- **脚本**：Python 3.10+（章节拆分）

## 快速开始

### 1. 克隆项目

```bash
git clone https://github.com/ImBintang/writing-assistant-xh.git
cd writing-assistant
```

### 2. 安装依赖

```bash
pnpm install
```

### 3. 配置 API Key

复制环境变量模板并填入你的 API Key：

```bash
cp .env.example .env
```

编辑 `.env` 文件，至少填入一个 AI 提供商的 API Key：

```env
ANTHROPIC_API_KEY=sk-ant-xxx   # Claude API
OPENAI_API_KEY=sk-xxx           # OpenAI API（可选）
OLLAMA_API_KEY=                 # Ollama 本地模型（可选）
```

> ⚠️ **`.env` 文件不会被 Git 追踪**，已在 `.gitignore` 中排除。

### 4. 启动

```bash
pnpm dev
```

- 后端运行在 `http://localhost:3000`
- 前端运行在 `http://localhost:5173`
- 在浏览器中打开 `http://localhost:5173` 即可使用

### 5. 构建生产版本（可选）

```bash
pnpm build
```

构建产物：`server/dist/` 和 `client/dist/`。

## 使用方法

### 典型工作流程

```
上传小说 → 拆分章节 → AI 提取知识 → 浏览/编辑知识库 → AI 辅助写作 → 完成
```

1. **上传小说**：在「章节管理」页面拖拽或点击上传 `.txt` 文件
2. **拆分章节**：系统自动按章节标题正则拆分，可手动调整规则
3. **提取知识**：在「知识提取」页面配置任务，AI 逐章提取人物、功法等信息
4. **管理知识**：在「知识库」页面搜索、编辑、版本回溯
5. **可视化**：在「知识图谱」页面查看知识网络关系
6. **开始写作**：在「写文窗口」输入大纲，AI 根据知识库上下文生成正文
7. **头脑风暴**：在「头脑风暴」页面与 AI 讨论剧情走向

## 文件存储说明

所有用户数据存储在项目根目录的 **`workspace/`** 文件夹中，完全本地化：

```
workspace/
├── originals/          ← 你上传的原始 .txt 文件
├── chapters/           ← 拆分后的章节文件
├── knowledge/          ← 知识库 JSON 文件（每条目一个文件）
│   ├── characters/     ←   人物
│   ├── techniques/     ←   功法
│   ├── locations/      ←   地图
│   ├── worldbuilding/  ←   世界观
│   ├── weapons/        ←   武器
│   ├── alchemy/        ←   丹药
│   ├── plot/           ←   情节
│   ├── _index.db       ←   SQLite 搜索索引
│   ├── _skills/        ←   自定义提取技能
│   └── _trash/         ←   软删除回收站
├── settings/           ← 设定构思文件 (.md)
├── drafts/             ← 写作草稿
└── logs/               ← 应用日志（按日轮转，保留 30 天）
```

> 🔒 **所有数据都在你的电脑上**，不会上传到任何云端服务器。

## API Key 安全

项目采用多重措施保护你的 API Key：

| 措施 | 说明 |
|------|------|
| **环境变量存储** | Key 存储在 `.env` 文件中，启动后仅存在于内存，不写入任何数据库或 JSON 文件 |
| **日志脱敏** | 日志系统会自动检测并遮蔽 API Key（支持 Anthropic、OpenAI 等 5 类格式），防止 Key 泄露到日志文件 |
| **前端屏蔽** | 配置页面查询 Key 状态时，只返回「已配置/未配置」状态，以及 `sk-a***xxxx` 格式的掩码 |
| **Git 排除** | `.env` 在 `.gitignore` 中，不会被提交到版本控制 |
| **本地运行** | 整个应用在你的电脑上运行，Key 仅用于直接调用 AI API，不经过任何中间服务器 |

---

## 数据安全

- **完全本地化**：所有文件、数据库、日志均存储在本地 `workspace/` 目录
- **沙箱隔离**：所有文件操作被限制在 `workspace/` 目录内，路径遍历攻击会被拦截并记录
- **系统文件保护**：`.workspace.lock`、`_meta.json` 等系统文件无法通过常规 API 修改
- **XSS 防护**：用户输入经过清洗，移除 `<script>` 标签和事件处理器
- **速率限制**：全局 120次/分钟、AI 操作 10次/分钟、上传 5次/分钟
- **上传限制**：仅允许 `.txt` 文件（章节上传），最大 50MB

## 常见问题

### Q: 启动报端口占用？

修改 `.env` 的 `PORT=3000` 为其他端口，同时修改 `client/vite.config.ts` 中的代理目标端口。

### Q: Python 拆分失败？

确保命令行中 `python`（Windows）或 `python3`（macOS/Linux）可用，且版本 >= 3.10。章节拆分使用纯标准库，无需额外安装。

### Q: 如何切换 AI 模型？

在「系统配置」页面可以：
- 添加自定义模型预设
- 为不同功能（提取/写作/润色）分配不同模型
- 测试模型连接

### Q: 如何备份数据？

直接复制整个 `workspace/` 文件夹到备份位置。你也可以在知识库页面使用「导出」功能导出 ZIP 包。

### Q: 删除的知识条目能恢复吗？

知识库使用软删除机制，删除的条目会进入回收站（`workspace/knowledge/_trash/`），可在知识库管理页面的回收站中恢复。
